# Using rclone with Auto Drive

## What is rclone?

[rclone](https://rclone.org) is an open-source command-line program, often described as "rsync for cloud storage", that syncs, copies, and serves files between local disks and 70+ cloud storage providers through a single, consistent interface. It is widely used for backups, archival, migrations, and as the backbone of many self-hosted file workflows.

Highlights of what rclone offers out of the box:

- **One CLI for many backends.** S3-compatible providers, Google Drive, Dropbox, Backblaze B2, Azure Blob, SFTP, WebDAV, and many more, all behind the same commands (`copy`, `sync`, `ls`, `mount`, etc.).
- **Resumable, parallel transfers.** Configurable parallelism, automatic retries, and skipping of files that are already up to date make large transfers safe to interrupt and re-run.
- **Integrity verification.** Built-in checksum comparison via `rclone check` and `rclone md5sum` confirms that what's stored matches what was sent.
- **Mount as a filesystem.** `rclone mount` exposes a remote as a FUSE filesystem so any tool can read remote files as if they were local.
- **Serve over HTTP, WebDAV, FTP, S3.** `rclone serve` turns any remote into a server that other tools can read from.
- **Encryption, compression, and chunking.** Built-in transformers can transparently encrypt or compress data before upload.
- **Scheduling-friendly.** Predictable exit codes, structured logs, and dry-run support make it easy to embed in cron, systemd timers, GitHub Actions, GitLab CI, or any orchestration system.

Auto Drive is a named rclone provider. From rclone v1.76.0, you pick **Autonomys Auto Drive** from rclone's provider list and rclone applies the right settings for you.

Auto Drive is **permanent storage**: everything you upload is written to the Autonomys Distributed Storage Network (DSN) and stays there. rclone works with it much as it does with any versioned S3 bucket:

- **Deleting hides a file.** `rclone delete`, `sync`, `move`, and `purge` work. A deleted file disappears from listings and downloads, but its data stays on the DSN.
- **Every version is kept.** Uploading new content to an existing path makes it the current version. Earlier versions stay readable.
- **Nothing can be erased.** Requests to destroy a specific version are refused.

The rest of this page is the technical reference for configuring rclone against Auto Drive and using it day-to-day.

## Quickstart

**1. Get an API key.** Sign in at [ai3.storage](https://ai3.storage), open the **Developers** section, and create an API key. A free tier is available for getting started.

**2. Install rclone v1.76.0 or later.**

```bash
# macOS
brew install rclone

# Linux
curl https://rclone.org/install.sh | sudo bash

# Windows
winget install Rclone.Rclone
```

Check your version with `rclone version`. If you installed rclone from [rclone.org](https://rclone.org/downloads/), `rclone selfupdate` upgrades it in place. If you installed it with a package manager, upgrade through the package manager, and check that it already ships v1.76.0, because package managers can lag behind rclone releases. On an older version, see [Older rclone versions](#older-rclone-versions).

**3. Configure the Auto Drive remote.** Create or edit `~/.config/rclone/rclone.conf` (Linux/macOS) or `%APPDATA%\rclone\rclone.conf` (Windows):

```ini
[autodrive]
type = s3
provider = Autonomys
access_key_id = YOUR_API_KEY_HERE
secret_access_key = placeholder
endpoint = s3.auto-drive.autonomys.xyz
```

**4. Verify the connection.**

```bash
# Copy a file to permanent storage (this creates the my-archive bucket)
rclone copy ./my-file.txt autodrive:my-archive/

# List your buckets
rclone lsd autodrive:

# Download it back
rclone copy autodrive:my-archive/my-file.txt ./downloaded/
```

## Configuration Reference

| Option | Value | Notes |
| --- | --- | --- |
| `type` | `s3` | Use rclone's S3 backend |
| `provider` | `Autonomys` | Auto Drive's named provider (rclone v1.76.0 and later) |
| `access_key_id` | Your Auto Drive API key | From the **Developers** tab at [ai3.storage](https://ai3.storage) |
| `secret_access_key` | Any non-empty string | Required by rclone but ignored by Auto Drive |
| `endpoint` | `s3.auto-drive.autonomys.xyz` | Option 1 in the endpoint menu of `rclone config` |

The `Autonomys` provider sets everything else Auto Drive needs, so you don't need any other options:

- Path-style requests, with listings that use ListObjectsV2 and URL-encoded keys.
- No bucket checks or `CreateBucket` calls, because buckets are created by the first upload into them.
- Server-side copies of any size in a single request.
- `rclone purge` hides the current files instead of trying to delete every version.

Always use the `s3.auto-drive.autonomys.xyz` endpoint. See [Legacy endpoint](#legacy-endpoint) if your config still points at `public.auto-drive.autonomys.xyz/s3`.

For local development against a self-hosted Auto Drive instance, keep `provider = Autonomys` and type your own endpoint at the endpoint prompt:

```ini
endpoint = http://localhost:3000/s3
```

### Interactive setup

If you prefer the interactive flow, run:

```bash
rclone config
```

1. Select `n` for new remote
2. Name it `autodrive`
3. Select `s3` (Amazon S3 Compliant Storage Providers)
4. Select `Autonomys` (Autonomys Auto Drive) as the provider
5. Enter `false` for `env_auth`
6. Enter your API key as `access_key_id`
7. Enter `placeholder` for `secret_access_key`
8. Choose `s3.auto-drive.autonomys.xyz` (Auto Drive mainnet S3 endpoint) as the endpoint
9. Accept the defaults for the remaining options

rclone's own [Auto Drive setup guide](https://rclone.org/s3/#autonomys) shows the full interactive session.

### Older rclone versions

rclone v1.75 and earlier have no `Autonomys` provider. Upgrade if you can. Otherwise use the generic provider and set the options the named provider would set for you:

```ini
[autodrive]
type = s3
provider = Other
access_key_id = YOUR_API_KEY_HERE
secret_access_key = placeholder
endpoint = https://s3.auto-drive.autonomys.xyz
no_check_bucket = true
list_version = 2
list_url_encode = true
```

| Option | Value | Notes |
| --- | --- | --- |
| `no_check_bucket` | `true` | **Required.** Auto Drive has no bucket-level endpoints, so rclone must not check for or create buckets |
| `list_version` | `2` | **Required.** Auto Drive implements ListObjectsV2 only. With `provider = Other`, rclone defaults to V1 and listings fail with "directory not found" |
| `list_url_encode` | `true` | Recommended. Without it, listing a path that contains keys with control characters fails with `400 InvalidArgument` |

Two commands behave differently with `provider = Other`:

- `rclone purge` fails with `403 AccessDenied`, because rclone tries to delete every version of every file. Use `rclone delete` instead.
- Server-side copies and moves of files of about 4.6 GiB or more fail with `501 NotImplemented`, because rclone copies them in parts. Add `--disable copy` to have rclone download and re-upload them instead.

## Bucket Model

Auto Drive treats the **first segment** of an object key as the bucket name. When you copy files to `autodrive:my-archive/`, rclone uses `my-archive` as the bucket and the remaining path as the key:

| rclone path | Bucket | Key |
| --- | --- | --- |
| `autodrive:my-archive/file.txt` | `my-archive` | `file.txt` |
| `autodrive:my-archive/sub/file.txt` | `my-archive` | `sub/file.txt` |

- **Buckets are created by the first upload** into them. There is no `CreateBucket` call, and a bucket disappears from listings once it has no visible files.
- **Buckets are private to your account.** `rclone lsd autodrive:` lists only your own buckets, and two accounts can use the same bucket and key names without seeing each other's files.
- **Objects uploaded before bucket support** (flat keys with no `/`) remain accessible in the `default` bucket.

## How deletes and versions work

| Action | What happens |
| --- | --- |
| Upload to a new path | The file is stored permanently on the DSN |
| Upload to an existing path | The new content becomes the current version. The previous version is kept and stays readable with `--s3-versions` |
| Delete a file | The file is hidden from listings and downloads. Its data stays on the DSN |
| Delete the last path that points at some content | The content also moves to the **Trash** in the web app at [ai3.storage](https://ai3.storage). Restoring it there makes the file visible again |
| Read a deleted file | Not possible with `--s3-versions`: the version that was current when you deleted it is listed but can't be read. Restore the file from the Trash instead |
| Destroy a specific version | Refused with `403 AccessDenied` |

Each version is stored separately and uses upload credits. Copies and moves within Auto Drive are server-side: the new path points at the existing content, so nothing is re-uploaded and no extra credits are used.

## Recommended Flags

| Flag | Purpose | When to use |
| --- | --- | --- |
| `--immutable` | Refuse to replace an existing file that has different content | Archives and records that must never change |
| `-v` / `--verbose` | Show progress and transfer details | Debugging |
| `--log-file=FILE` | Write logs to a file | Production and CI/CD |
| `--transfers=N` | Number of parallel transfers (default: 4) | Large jobs |
| `--ignore-checksum` | Skip MD5 checksum comparison | Legacy objects without MD5 ETags |
| `--size-only` | Compare by size instead of checksum | Alternative to `--ignore-checksum` |

### When to use `--immutable`

Overwriting a file on Auto Drive works, but it is never free: the new version is stored permanently and uses upload credits, and the old version stays on the DSN too. For an archive whose contents should never change, add `--immutable`. rclone then stops with `immutable file modified` instead of uploading a changed local file over the stored one, which catches mistakes such as a source file modified after it was archived. Files that are already identical are skipped either way, so `--immutable` isn't needed to make a copy resumable.

Leave it off when you mean to update files, for example with `rclone sync` to mirror a folder that changes.

### A note on checksums

Auto Drive returns standard MD5 hashes as S3 ETags for all objects uploaded after MD5 ETag support was introduced, including multipart uploads. `rclone check` and `rclone md5sum` work correctly on those objects without any special flags.

Objects uploaded before MD5 ETag support have no stored MD5. For those legacy objects, add `--ignore-checksum` or `--size-only` to skip checksum comparison.

## Operations Reference

### Uploading

#### `copy` (upload)

Copies files from source to destination without deleting source files. The primary command for archiving to Auto Drive.

```bash
# Single file
rclone copy ./report.pdf autodrive:my-archive/reports/

# Whole directory
rclone copy ./backup/ autodrive:my-archive/backup-2026-05-03/ -v

# An archive that must never change
rclone copy ./records/ autodrive:my-archive/records/ --immutable -v
```

Files under 200 MiB are uploaded in a single request. Larger files, and uploads of unknown size, use multipart upload.

#### `copyto`: copy a single file to a specific path

```bash
rclone copyto ./local-file.txt autodrive:my-archive/archive/renamed-file.txt
```

#### `rcat`: upload from stdin

```bash
echo "log entry" | rclone rcat autodrive:my-archive/logs/entry.txt
tar czf - ./project/ | rclone rcat autodrive:my-archive/archives/project.tar.gz
```

### Downloading and reading

#### `copy` (download)

```bash
rclone copy autodrive:my-archive/reports/report.pdf ./downloaded/
rclone copy autodrive:my-archive/backup-2026-05-03/ ./restored/
```

Byte-range downloads are supported. Reading a file of 100 MiB or less is free. Reading a larger file uses download credits from your free tier for the bytes read (purchased credits don't add download credits), and fails with `402 PaymentRequired` if you don't have enough. Listing files and reading their size and metadata are free at any size.

#### `cat`: read file contents to stdout

```bash
rclone cat autodrive:my-archive/logs/app.log

# Read part of a file
rclone cat autodrive:my-archive/logs/app.log --offset 1024 --count 512
```

### Listing

#### `ls` / `lsl` / `lsjson`: list files

```bash
rclone ls autodrive:my-archive/
rclone lsl autodrive:my-archive/reports/

# Include metadata, such as Content-Type, user metadata and the content CID
rclone lsjson --metadata autodrive:my-archive/reports/report.pdf
```

`lsl` shows the modification time rclone recorded at upload.

#### `lsd`: list buckets or directories

```bash
# All your buckets
rclone lsd autodrive:

# Top-level virtual directories in a bucket
rclone lsd autodrive:my-archive/
```

The top-level form uses `ListBuckets`; the per-bucket form uses `ListObjectsV2` with delimiter folding.

#### `tree`: recursive tree view

```bash
rclone tree autodrive:my-archive/
```

#### `size`: total size and count

```bash
rclone size autodrive:my-archive/
rclone size autodrive:my-archive/reports/
```

Counts current versions only.

### Verifying

#### `md5sum`, `check`, `hashsum`

```bash
rclone md5sum autodrive:my-archive/
rclone check ./local/ autodrive:my-archive/
rclone hashsum md5 autodrive:my-archive/
```

All three use the MD5 ETag for verification. `rclone md5sum` is shorthand for `rclone hashsum md5`; only `md5` is supported because Auto Drive stores MD5 ETags. Add `--ignore-checksum` for legacy objects without a stored MD5.

### Changing and removing files

#### `delete` / `deletefile`

```bash
# Delete everything under a prefix
rclone delete autodrive:my-archive/old-reports/

# Delete one file
rclone deletefile autodrive:my-archive/reports/draft.pdf
```

The files are hidden from listings and downloads, and their data stays on the DSN. To get a deleted file back, restore it from the Trash in the web app. See [How deletes and versions work](#how-deletes-and-versions-work).

#### `purge`

```bash
rclone purge autodrive:my-archive/old/
```

Hides every file under the path, like `rclone delete`. Directories are virtual, so the path disappears once it has no visible files. With `provider = Other`, `purge` fails with `403 AccessDenied`; use `rclone delete` instead.

#### `move` / `moveto`

```bash
# Rename a file
rclone moveto autodrive:my-archive/draft.pdf autodrive:my-archive/final.pdf

# Move a directory to another bucket
rclone move autodrive:my-archive/2025/ autodrive:cold-archive/2025/

# Upload local files, then remove the local copies
rclone move ./outbox/ autodrive:my-archive/inbox/
```

Moves within Auto Drive are a server-side copy followed by a delete, so nothing is re-uploaded.

#### Server-side copy

```bash
rclone copy autodrive:my-archive/reports/ autodrive:shared-reports/
```

The new path points at the existing content, so nothing is re-uploaded and no extra credits are used.

#### `sync`

```bash
rclone sync ./local/ autodrive:my-archive/mirror/
```

New and changed files are uploaded. Files that are no longer in the source are deleted at the destination, which hides them; their data stays on the DSN. To keep replaced and removed files at another path instead, add `--backup-dir`:

```bash
rclone sync ./local/ autodrive:my-archive/mirror/ \
  --backup-dir autodrive:my-archive/mirror-history/$(date +%Y%m%d)
```

#### `mount`

```bash
mkdir -p /mnt/autodrive

# Read-only mount, for browsing
rclone mount autodrive:my-archive/ /mnt/autodrive \
  --read-only \
  --vfs-cache-mode full \
  --vfs-read-chunk-size 5M

# Read-write mount
rclone mount autodrive:my-archive/ /mnt/autodrive \
  --vfs-cache-mode writes
```

| Flag | Purpose |
| --- | --- |
| `--read-only` | Browse without the risk of accidental writes |
| `--vfs-cache-mode full` | Caches files locally for better read performance |
| `--vfs-cache-mode writes` | Needed for applications that edit files in place |
| `--vfs-read-chunk-size 5M` | Reads files in 5 MB chunks for efficient streaming |

In a read-write mount, creating, renaming and deleting files work, but every save of a file uploads a new permanent version and uses credits. Editors that save often can use more storage than you expect, so prefer `--read-only` unless you need to write.

Unmount with:

```bash
fusermount -u /mnt/autodrive   # Linux
umount /mnt/autodrive          # macOS
```

### Versions

Versioning is always on and cannot be turned off. Each version's ID is its content CID.

```bash
# List all versions, including overwritten and deleted files
rclone ls --s3-versions autodrive:my-archive/reports/

# Read the bucket as it was at a point in time
rclone copy --s3-version-at "2026-09-01 00:00:00" \
  autodrive:my-archive/reports/ ./reports-as-of-sept/

# Check that versioning is enabled
rclone backend versioning autodrive:my-archive
```

With `--s3-versions`, older versions appear with a timestamp suffix in the file name (for example `report-v2026-09-01-120000-000.pdf`), and you can download them like any other file. To copy an older version to another path within Auto Drive, add `--disable copy` (see [Recover an overwritten file](#recover-an-overwritten-file)). A deleted file's last version is listed but can't be read; restore the file from the Trash instead.

Version history starts from when Auto Drive began recording versions, so files last written before then show only their current version.

Versions are permanent. Commands that destroy a version are refused with `403 AccessDenied`:

- `rclone deletefile --s3-versions` on an old version
- `rclone backend cleanup-hidden`

### Sharing files

`rclone link` is not supported. rclone builds a presigned S3 URL, and Auto Drive does not accept presigned URLs, so the link returns `403 AccessDenied`.

To share a file, use its permanent link on the Autonomys gateway:

```
https://gateway.autonomys.xyz/file/<CID>
```

The CID is in the file's metadata as `cid`:

```bash
rclone lsjson --metadata autodrive:my-archive/report.pdf
```

A gateway link is public: anyone who has it can read the file.

### Commands with no effect or no support

- **`mkdir`** succeeds but does nothing. Buckets and directories are virtual, and a bucket appears when you upload the first file into it.
- **`rmdir` / `rmdirs`** succeed but do nothing. A directory or bucket disappears once it has no visible files. `rmdir` reports success even on a path that still contains files, and leaves those files in place.
- **`cleanup`** fails with `501 NotImplemented`, because Auto Drive does not implement `ListMultipartUploads`. rclone aborts its own failed multipart uploads automatically, so there is normally nothing to clean up.
- **`about`** is not supported: there is no quota API. Check your storage and credit balance at [ai3.storage](https://ai3.storage).

## Workflows

### Archive a local directory

```bash
rclone copy ./important-data/ autodrive:my-archive/important-data/ \
  --immutable \
  -v
```

Re-running the same command after adding files uploads only the new ones, so large transfers are safe to interrupt and resume. `--immutable` makes rclone stop instead of overwriting an archived file whose local copy has since changed.

### Scheduled archival with cron

A cron-ready archive script template:

```bash
#!/usr/bin/env bash
set -euo pipefail

SOURCE_DIR="${SOURCE_DIR:-/path/to/your/data}"
BUCKET="${BUCKET:-my-archive}"
DEST_PREFIX="${DEST_PREFIX:-daily}"
REMOTE="autodrive"
TRANSFERS="${TRANSFERS:-4}"

TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
echo "[$TIMESTAMP] Starting archive: $SOURCE_DIR -> $REMOTE:$BUCKET/$DEST_PREFIX/"

rclone copy "$SOURCE_DIR" "$REMOTE:$BUCKET/$DEST_PREFIX/" \
  --immutable \
  --transfers "$TRANSFERS" \
  -v
```

Crontab entry (daily at 02:00):

```
0 2 * * * BUCKET=my-archive SOURCE_DIR=/path/to/data /path/to/archive-script.sh >> /var/log/autodrive-archive.log 2>&1
```

### Browse and verify

```bash
rclone lsd autodrive:                                 # all buckets
rclone lsd autodrive:my-archive/                      # top-level dirs in bucket
rclone ls  autodrive:my-archive/                      # all files
rclone ls  autodrive:my-archive/reports/              # files under prefix
rclone tree autodrive:my-archive/                     # recursive tree
rclone check ./local/ autodrive:my-archive/           # verify checksums
rclone cat autodrive:my-archive/logs/app.log          # stream a file
```

### Read-only mount

```bash
mkdir -p /mnt/autodrive
rclone mount autodrive:my-archive/ /mnt/autodrive \
  --read-only \
  --vfs-cache-mode full \
  --vfs-read-chunk-size 5M
```

Then browse with any standard tool:

```bash
ls /mnt/autodrive/
cat /mnt/autodrive/reports/q1.pdf
```

### Recover an overwritten file

```bash
# Find the earlier version
rclone ls --s3-versions autodrive:my-archive/reports/

# Download it
rclone copyto --s3-versions \
  autodrive:my-archive/reports/report-v2026-09-01-120000-000.pdf \
  ./report-restored.pdf

# Or make it the current version again
rclone copyto --s3-versions --disable copy \
  autodrive:my-archive/reports/report-v2026-09-01-120000-000.pdf \
  autodrive:my-archive/reports/report.pdf

# Or download a whole directory as it was at a point in time
rclone copy --s3-version-at "2026-09-01 00:00:00" \
  autodrive:my-archive/reports/ ./reports-2026-09-01/
```

Always add `--disable copy` when copying an earlier version to a path on Auto Drive. A server-side copy always copies a file's current version, not the version you named, so rclone would report the result as corrupted and delete it. With `--disable copy`, rclone downloads the earlier version and uploads it again, which uses upload credits.

### Recover a deleted file

Open the **Trash** in the web app at [ai3.storage](https://ai3.storage) and restore the file. It becomes visible again at its old path.

### Migrate from another cloud provider

The pattern is the same regardless of source remote:

```bash
rclone copy <source>:<source-path>/ autodrive:<bucket>/<dest-prefix>/ --immutable -v
```

```bash
# AWS S3
rclone copy s3:my-source-bucket/data/ autodrive:migrated/aws-data/ --immutable -v

# Google Cloud Storage
rclone copy gcs:my-gcs-bucket/archives/ autodrive:migrated/gcs-archives/ --immutable -v

# Backblaze B2
rclone copy b2:my-b2-bucket/ autodrive:migrated/b2-backup/ --immutable -v
```

Tips for large migrations:

- Use `-v` or `--progress` to monitor progress
- Tune `--transfers=N` to your bandwidth
- Capture full logs with `--log-file=migration.log`
- Run inside `screen` or `tmux` for long jobs
- If the job is interrupted, re-run the same command: files already uploaded are skipped
- Every file written uses upload credits, so check the total first with `rclone size <source>:<source-path>/`

### CI/CD integration

The examples below define the remote with `RCLONE_CONFIG_<REMOTE>_<OPTION>` environment variables, so no config file is needed and the API key is never written to disk.

#### GitHub Actions

```yaml
name: Archive Build Artifacts

on:
  push:
    branches: [main]

jobs:
  build-and-archive:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: make build

      - name: Install rclone
        run: curl https://rclone.org/install.sh | sudo bash

      - name: Archive build artifacts
        env:
          RCLONE_CONFIG_AUTODRIVE_TYPE: s3
          RCLONE_CONFIG_AUTODRIVE_PROVIDER: Autonomys
          RCLONE_CONFIG_AUTODRIVE_ACCESS_KEY_ID: ${{ secrets.AUTO_DRIVE_API_KEY }}
          RCLONE_CONFIG_AUTODRIVE_SECRET_ACCESS_KEY: placeholder
          RCLONE_CONFIG_AUTODRIVE_ENDPOINT: s3.auto-drive.autonomys.xyz
        run: |
          TIMESTAMP=$(date +%Y%m%d-%H%M%S)
          rclone copy ./dist/ \
            "autodrive:ci-builds/${GITHUB_SHA}-${TIMESTAMP}/" \
            -v
```

#### GitLab CI

```yaml
archive-artifacts:
  stage: deploy
  image:
    name: rclone/rclone:latest
    # The image's entrypoint is rclone itself; clear it so GitLab can run the script
    entrypoint: [""]
  variables:
    RCLONE_CONFIG_AUTODRIVE_TYPE: s3
    RCLONE_CONFIG_AUTODRIVE_PROVIDER: Autonomys
    RCLONE_CONFIG_AUTODRIVE_SECRET_ACCESS_KEY: placeholder
    RCLONE_CONFIG_AUTODRIVE_ENDPOINT: s3.auto-drive.autonomys.xyz
  script:
    # AUTO_DRIVE_API_KEY is a masked CI/CD variable
    - export RCLONE_CONFIG_AUTODRIVE_ACCESS_KEY_ID="${AUTO_DRIVE_API_KEY}"
    - TIMESTAMP=$(date +%Y%m%d-%H%M%S)
    - rclone copy ./dist/ "autodrive:ci-builds/${CI_COMMIT_SHA}-${TIMESTAMP}/" -v
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
```

### Compliance and audit logs

Permanent storage suits retention requirements: once written, content stays on the DSN and every version is kept, even if a file is later deleted or overwritten.

```bash
# Daily application logs
rclone copy /var/log/app/ autodrive:compliance/logs/$(date +%Y/%m/%d)/ \
  --immutable \
  --include "*.log"

# Database backup
pg_dump mydb | rclone rcat autodrive:compliance/db-backups/$(date +%Y%m%d-%H%M%S).sql
```

### Run rclone in Docker

The official rclone image works against Auto Drive with the remote defined in environment variables. Below is a `docker-compose.yml` that serves a bucket over HTTP (read-only) using `rclone serve http`, which is simpler than a FUSE mount in containers since FUSE requires `--privileged` or `--cap-add SYS_ADMIN`.

```yaml
services:
  rclone:
    image: rclone/rclone:latest
    container_name: rclone-autodrive
    restart: unless-stopped
    environment:
      RCLONE_CONFIG_AUTODRIVE_TYPE: s3
      RCLONE_CONFIG_AUTODRIVE_PROVIDER: Autonomys
      RCLONE_CONFIG_AUTODRIVE_ACCESS_KEY_ID: ${AUTO_DRIVE_API_KEY:?Set AUTO_DRIVE_API_KEY environment variable}
      RCLONE_CONFIG_AUTODRIVE_SECRET_ACCESS_KEY: placeholder
      RCLONE_CONFIG_AUTODRIVE_ENDPOINT: s3.auto-drive.autonomys.xyz
    volumes:
      - ./data:/data:ro
    ports:
      # The HTTP server has no authentication, so bind it to localhost only
      - '127.0.0.1:8181:8181'
    command:
      - serve
      - http
      - autodrive:${AUTO_DRIVE_BUCKET:-my-archive}/
      - --addr
      - :8181
      - --read-only
      - --vfs-cache-mode
      - full
```

To upload from inside the container:

```bash
docker compose exec rclone rclone copy /data autodrive:my-archive/
```

## Troubleshooting

### Checksum mismatch on legacy objects

**Symptom:**

```
ERROR : file.txt: corrupted on transfer: md5 hash differ "abc123" vs "bafkr..."
```

**Cause:** The object was uploaded before MD5 ETag support shipped, so its ETag is the CID, which rclone interprets as a failed checksum.

**Fix:** Add `--ignore-checksum` (or `--size-only`) to your command:

```bash
rclone copy ./files/ autodrive:my-archive/ --ignore-checksum
```

Objects uploaded after the MD5 ETag feature do not need this flag.

### Legacy endpoint

**Symptoms:** Files stored with `Content-Encoding: gzip` download decompressed or fail their checksum, HTML files come back altered, or uploads of about 100 MB fail.

**Cause:** Your remote uses the older endpoint `https://public.auto-drive.autonomys.xyz/s3`. It still works for existing clients, but it runs through a CDN that can change responses and limits upload size.

**Fix:** Switch to the dedicated S3 endpoint, which returns stored bytes exactly:

```bash
rclone config update autodrive endpoint s3.auto-drive.autonomys.xyz
```

### Upload fails with 413 EntityTooLarge

**Symptom:** `api error EntityTooLarge` on a large upload.

**Cause:** Auto Drive accepts at most 200 MiB in a single request. rclone's defaults stay under this: files of 200 MiB or more use multipart upload. The error appears if `--s3-upload-cutoff` or `--s3-chunk-size` is raised above 200 MiB.

**Fix:** Leave `--s3-upload-cutoff` and `--s3-chunk-size` at their defaults, or set them to `200M` or less.

### Purge fails with 403 AccessDenied

**Cause:** Your remote uses `provider = Other`. Auto Drive reports versioning as enabled, so rclone's S3 purge tries to delete every version of every file, and versions cannot be destroyed.

**Fix:** Upgrade to rclone v1.76.0 or later and switch to the named provider, or use `rclone delete` instead:

```bash
rclone config update autodrive provider Autonomys
```

### Listing fails with "directory not found" (older rclone)

**Symptom:** With `provider = Other`, `rclone ls`, `rclone lsd`, `rclone check`, or `rclone sync` fail with `directory not found` or `404 NoSuchKey`.

**Cause:** Auto Drive implements **ListObjectsV2** only. With `provider = Other`, rclone uses the older **ListObjectsV1** API by default, which Auto Drive does not recognise.

**Fix:** Switch to the named provider (rclone v1.76.0 and later), or set `list_version = 2`:

```bash
rclone config update autodrive list_version 2
```

### 503 Service Unavailable or SlowDown

**Cause:** Auto Drive rate-limits requests and answers with `503` when a client sends too many at once. An object that was uploaded moments ago can also be briefly unavailable, with a `503` that says to retry.

**Fix:** rclone retries `503` responses automatically. If they persist, reduce parallelism with `--transfers` and `--checkers`, or cap the request rate with `--tpslimit`.

### 402 PaymentRequired

**Cause:** Your account doesn't have enough credits for the request. Uploads use upload credits. Reading a file larger than 100 MiB uses download credits.

**Fix:** Check your balance at [ai3.storage](https://ai3.storage) and top up if required.

### Authentication errors

**Symptoms:** `403 InvalidAccessKeyId` or `AccessDenied`.

**Possible causes:**

1. The API key is incorrect or has been revoked
2. The API key has expired (if you set an expiry)

**Fix:**

- Verify the key at [ai3.storage](https://ai3.storage) → Developers
- Create a new key if needed
- Confirm `access_key_id` in your rclone config matches the API key exactly

### Connection timeouts

**Symptom:** `Failed to copy: connection timed out`.

**Fix:**

- `curl -I https://s3.auto-drive.autonomys.xyz` to verify reachability
- Increase the timeout: `--timeout=60s`
- Add retries: `--retries=5 --retries-sleep=10s`

### Immutable file conflict

**Symptom:** `Failed to copy: immutable file modified`.

**Cause:** `--immutable` is set and the destination already has a file at the same path with different content.

- If the local file changed by mistake, the stored copy is unchanged and nothing was uploaded.
- If you want to replace the file, run the command without `--immutable`. The new content becomes the current version, and the old version stays readable with `--s3-versions`.

### Diagnostic commands

```bash
# Inspect rclone config
rclone config show autodrive

# Test endpoint reachability
curl -I https://s3.auto-drive.autonomys.xyz

# Verbose upload with full logging
rclone copy ./test.txt autodrive:test-bucket/ \
  -vv \
  --log-file=rclone-debug.log \
  --dump headers

# rclone version (v1.76.0 or later for provider = Autonomys)
rclone version
```
